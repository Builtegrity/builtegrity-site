Customer fields & integrations

Organize customers, purchases and individual payments with the titles used in your business. Keep your existing software. Import structured records or connect an automated feed; Builtegrity keeps financial processor evidence separate from merchant-supplied details.

Checking merchant permissions…

You must be an owner of the merchant account to change fields or integration keys. Builtegrity support does not need passwords or access to your bank, files or internal system.

1. Name what you want to track

Automatic or manual? After you create each field, choose Automatic from connected source and select the software that sends it. The field updates as soon as Builtegrity receives a matching, authorized value. If that source cannot send updates, choose Manual or CSV/JSON upload. Payments and payouts continue updating from Stripe or Square independently.

Examples: HOA Community, Service Route, Property ID, Invoice Category, Cart Count, Sales Representative, Contract Number. Customer fields follow that customer; transaction fields describe a particular payment. You control whether fields appear in your merchant PDF.

2. Connect where your records live

Connection status: a source heartbeat confirms the sender is reachable, not that a value changed. We never invent values while a software provider is delayed. For unsupported systems, request a connector through Help; you can still use manual entries while waiting.

Choose a structured file for one-time imports, or a push feed for continuing updates. Databases can push through an existing app, workflow tool, or change-data-capture relay. SaaS apps must support outgoing webhooks/API automation or have a dedicated Builtegrity connector. This is not a direct connection to every database or third-party service.

For an automated feed, send a stable event ID and one or more customer/transaction references matching those already in your own system.

{
  "delivery_id": "RR-ERP-EVENT-0042",
  "records": [
    {
      "scope": "CUSTOMER",
      "external_reference": "RR-HOA-001",
      "fields": { "hoa_community": "West Bay HOA" }
    },
    {
      "scope": "TRANSACTION",
      "external_reference": "RR-HOA-2026-10",
      "fields": { "cart_count": 60 }
    }
  ]
}

This is an example only: first create both custom field keys, and use your actual customer and payment references. Duplicate delivery IDs are recognized and not reapplied. For zero-cost/Free Cloudflare capacity, send at most 8 records per request and 4 custom fields per record; larger updates must be split automatically by your sender.

3. Import customer and payment details

Upload UTF-8 CSV or JSON with columns scope, external_reference, followed by keys you created above. A customer reference must match the customer's merchant reference; a transaction reference must match the merchant's payment/receipt reference. Builtegrity never guesses matches. File uploads are not automatically synchronized after upload.

4. Browse customer groups and histories

Filter customers by a field you defined. Each group shows how many customers and recorded transactions match it. Select a group to see each customer and associated transaction history.

Understand your source data

Merchant-provided fields are descriptions, not independent payment verification. Stripe/Square supply authoritative payment facts; bank-posted evidence requires a separate authorized bank connection. Updates arrive when the connected provider sends them, with possible delays, outages, and renewed authorization. Your payment history remains available if an optional integration disconnects.
