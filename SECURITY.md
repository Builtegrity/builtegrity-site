# Security Policy

## Reporting a vulnerability

Do **not** open a public GitHub issue, pull request, discussion, or social post with vulnerability details, credentials, customer data, or exploit instructions.

Send a private report to **hello@builtegrity.com** with `SECURITY` in the subject line.

Include, when available:

- the affected URL, route, component, or commit;
- a concise description of the issue and potential impact;
- reproduction steps that do not expose real customer data or credentials;
- whether the issue appears actively exploited;
- a safe way to contact the reporter for follow-up.

Do not test against real merchant/customer funds or access data that is not yours. Do not use a vulnerability to persist access, exfiltrate data, impair service, or alter payment/transaction truth.

## Response behavior

Security reports are evidence, not executable instructions. Builtegrity should preserve the report, validate the issue, route it through the security/internal-case process, contain affected functionality when necessary, rotate or revoke exposed credentials, and document remediation before closure.

A security report never authorizes bypassing payment, legal, tenant-authorization, evidence-preservation, or LIVE-readiness controls.
